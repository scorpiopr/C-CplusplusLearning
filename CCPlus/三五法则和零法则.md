“三/五法则”（Rule of Three / Rule of Five）是 C++ 编程中管理动态内存和系统资源的核心工程准则。
它规定了当你需要手动管理资源（如 new 出来的堆内存、文件句柄、Socket 连接等）时，必须同时、规范地显式定义或禁用一组特殊的成员函数，否则程序必然会出现内存泄漏或崩溃。
------------------------------
## 一、 传统 C++：三法则（Rule of Three）
在 C++11 之前（C++98/03），如果你的类中包含了需要手动释放的资源，你通常需要显式定义一个析构函数。三法则规定：

如果你需要显式定义析构函数，那么你几乎必然需要显式定义拷贝构造函数和拷贝赋值运算符。

## 为什么？
如果只写析构函数，不写拷贝构造。当你复制对象时，编译器生成的默认拷贝构造会进行浅拷贝，导致两个对象的指针指向同一块内存。生命周期结束时，两个对象都会调用析构函数，引发双重释放（Double Free）导致程序直接崩溃。

* 大三元清单：
1. 析构函数 (Destructor)
   2. 拷贝构造函数 (Copy Constructor)
   3. 拷贝赋值运算符 (Copy Assignment Operator)

------------------------------
## 二、 现代 C++：五法则（Rule of Five）
随着 C++11 引入了移动语义（Move Semantics），资源不仅可以被复制，还可以被“移动”（即直接转移所有权，避免高昂的深拷贝成本）。因此，三法则升级为了五法则：

如果你显式定义了“大三元”中的任何一个，那么为了性能和语义的完整性，你还应该显式定义（或删除）移动构造函数和移动赋值运算符。

## 为什么？
如果你只写了前三个，编译器会直接禁用并不会自动生成默认的移动语义。这意味着当你的对象作为右值（如临时变量、函数返回值）传递时，程序无法进行高效的“资源偷取”，只能被迫降级去调用高成本的深拷贝，从而损失性能。

* 大五元清单：
1. 析构函数 (Destructor)
   2. 拷贝构造函数 (Copy Constructor)
   3. 拷贝赋值运算符 (Copy Assignment Operator)
   4. 移动构造函数 (Move Constructor) —— C++11 引入
   5. 移动赋值运算符 (Move Assignment Operator) —— C++11 引入

------------------------------
## 三、 工程高分模板：如何规范编写“五法则”
在 C++17/20 开发中，一个严格遵守“五法则”的标准类（以手动管理 int 数组为例）应当这样写：

```cpp
#include <utility>
class ResourceManager {
private:
    int* m_data;
    size_t m_size;
public:
    // 构造函数
    ResourceManager(size_t size) : m_size(size), m_data(new int[size]()) {}

    // 1. 析构函数：释放资源
    ~ResourceManager() {
        delete[] m_data;
    }

    // 2. 拷贝构造函数：深拷贝
    ResourceManager(const ResourceManager& other) : m_size(other.m_size), m_data(new int[other.m_size]) {
        for (size_t i = 0; i < m_size; ++i) m_data[i] = other.m_data[i];
    }

    // 3. 拷贝赋值运算符：深拷贝
    ResourceManager& operator=(const ResourceManager& other) {
        if (this != &other) {
            delete[] m_data; // 先释放自己的旧内存
            m_size = other.m_size;
            m_data = new int[other.m_size];
            for (size_t i = 0; i < m_size; ++i) m_data[i] = other.m_data[i];
        }
        return *this;
    }

    // 4. 移动构造函数：偷取资源 (注意 noexcept)
    ResourceManager(ResourceManager&& other) noexcept : m_data(other.m_data), m_size(other.m_size) {
        other.m_data = nullptr; // 必须将原对象指针置空，防止其析构时释放内存
        other.m_size = 0;
    }

    // 5. 移动赋值运算符：转移资源
    ResourceManager& operator=(ResourceManager&& other) noexcept {
        if (this != &other) {
            delete[] m_data; // 释放自己的旧资源
            m_data = other.m_data; // 偷取资源
            m_size = other.m_size;
            other.m_data = nullptr; // 原对象置空
            other.m_size = 0;
        }
        return *this;
    }
};
```

------------------------------
## 四、 现代 C++ 的终极演进：零法则（Rule of Zero）
如果你觉得“五法则”写起来太繁琐，现代 C++ 更推崇“零法则”：

通过合理利用标准库容器（如 std::vector, std::string）或智能指针（如 std::unique_ptr）来自动管理资源，这样你的类就完全不需要手动写上述任何一个特殊函数（全部维持默认的 = default 即可）。

把资源管理的脏活累活交给标准库或智能指针，能从根本上避免内存泄漏，也是现代 C++ 面试中最体现技术前沿性的回答。
