## 一、 独占型智能指针：UniquePtr 的手写实现
UniquePtr 的核心逻辑是独占所有权。因此，它的拷贝构造函数和拷贝赋值运算符必须被禁用（= delete），但需要支持移动语义（Move Semantics）来转移所有权。
## 最佳 C++ 实现代码（C++17 标准）
```cpp
#include <iostream>
#include <utility>
template <typename T>class UniquePtr {
public:
    // 1. 构造函数
    explicit UniquePtr(T* ptr = nullptr) : m_ptr(ptr) {}

    // 2. 析构函数：释放托管的内存
    ~UniquePtr() {
        reset();
    }

    // 3. 【核心】禁用拷贝构造和拷贝赋值，防止多个指针指向同一块内存
    UniquePtr(const UniquePtr&) = delete;
    UniquePtr& operator=(const UniquePtr&) = delete;

    // 4. 【核心】支持移动构造函数
    UniquePtr(UniquePtr&& other) noexcept : m_ptr(other.m_ptr) {
        other.m_ptr = nullptr; // 剥夺原指针的所有权
    }

    // 5. 【核心】支持移动赋值运算符
    UniquePtr& operator=(UniquePtr&& other) noexcept {
        if (this != &other) {
            reset();               // 释放自己当前的内存
            m_ptr = other.m_ptr;   // 接管新内存
            other.m_ptr = nullptr; // 剥夺原指针的所有权
        }
        return *this;
    }

    // 6. 运算符重载：实现类似裸指针的操作
    T& operator*() const { return *m_ptr; }
    T* operator->() const { return m_ptr; }

    // 7. 核心成员接口
    T* get() const { return m_ptr; }

    T* release() noexcept {
        T* temp = m_ptr;
        m_ptr = nullptr;
        return temp;
    }

    void reset(T* ptr = nullptr) {
        if (m_ptr) {
            delete m_ptr;
        }
        m_ptr = ptr;
    }

    // 支持 if(ptr) 隐式布尔类型转换
    explicit operator bool() const { return m_ptr != nullptr; }
private:
    T* m_ptr; // 托管的原始裸指针
};
```

## 二、 引用计数型智能指针：SharedPtr 的手写实现
SharedPtr 的核心是多个指针共享同一块内存，并通过一个位于堆上的引用计数器（Reference Count）来管理生命周期。当最后一个 SharedPtr 被销毁时，才真正释放用户的数据内存。
注：为了满足多线程高并发面试要求，底层的引用计数必须使用原子的 std::atomic<int>，否则在多线程环境中会引发严重的内存竞态（Race Condition）导致多次释放。
## 最佳 C++ 实现代码（C++17 标准）
```cpp
#include <iostream>
#include <atomic>
template <typename T>class SharedPtr {
public:
    // 1. 默认与有参构造函数
    explicit SharedPtr(T* ptr = nullptr) : m_ptr(ptr) {
        if (m_ptr) {
            m_refCount = new std::atomic<int>(1); // 必须在堆上创建原子计数器
        } else {
            m_refCount = nullptr;
        }
    }

    // 2. 析构函数：递减计数，降为0时彻底销毁内存
    ~SharedPtr() {
        release();
    }

    // 3. 【核心】拷贝构造函数：增加引用计数
    SharedPtr(const SharedPtr& other) : m_ptr(other.m_ptr), m_refCount(other.m_refCount) {
        if (m_refCount) {
            (*m_refCount)++; // 原子自增
        }
    }

    // 4. 【核心】拷贝赋值运算符：既有递减旧计数，又有增加新计数
    SharedPtr& operator=(const SharedPtr& other) {
        if (this != &other) {
            release(); // 1. 先安全释放自己当前持有的旧指针所有权
            
            // 2. 复制新指针和计数器
            m_ptr = other.m_ptr;
            m_refCount = other.m_refCount;
            if (m_refCount) {
                (*m_refCount)++; // 3. 原子自增新计数
            }
        }
        return *this;
    }

    // 5. 【加分项】移动构造函数
    SharedPtr(SharedPtr&& other) noexcept : m_ptr(other.m_ptr), m_refCount(other.m_refCount) {
        other.m_ptr = nullptr;
        other.m_refCount = nullptr; // 移动不改变计数器数值，直接交接指针
    }

    // 6. 【加分项】移动赋值运算符
    SharedPtr& operator=(SharedPtr&& other) noexcept {
        if (this != &other) {
            release(); // 释放自己持有的旧资源
            
            m_ptr = other.m_ptr;
            m_refCount = other.m_refCount;
            
            other.m_ptr = nullptr;
            other.m_refCount = nullptr;
        }
        return *this;
    }

    // 7. 指针运算符重载
    T& operator*() const { return *m_ptr; }
    T* operator->() const { return m_ptr; }

    // 8. 核心公共接口
    T* get() const { return m_ptr; }
    int use_count() const { return m_refCount ? m_refCount->load() : 0; }

    explicit operator bool() const { return m_ptr != nullptr; }
private:
    T* m_ptr;                      // 指向托管的数据对象
    std::atomic<int>* m_refCount;  // 指向位于堆上的原子引用计数器

    // 内部私有辅助释放函数
    void release() {
        if (m_refCount) {
            // 原子自减，如果减到 0 证明自己是全天下最后一个占有者
            if (--(*m_refCount) == 0) {
                delete m_ptr;       // 销毁用户对象
                delete m_refCount;  // 销毁计数器
                std::cout << "[Debug] Memory Logically Deleted!\n";
            }
        }
        m_ptr = nullptr;
        m_refCount = nullptr;
    }
};
```

## 三、 面试必问的底层细节与防御性回答

   1. 为什么 m_refCount 必须是指针（std::atomic<int>*）？
   因为引用计数需要被指向同一个原始对象的多个不同 SharedPtr 实例所共享。如果定义成普通成员变量 std::atomic<int> m_refCount;，那么在拷贝构造时它会被复制到新对象的栈里，各个智能指针之间的计数就完全脱节了。
   2. 为什么构造函数要加 explicit 关键字？
   防止隐式类型转换带来的严重灾难。例如若不加 explicit，写出 SharedPtr<int> ptr = new int(10); 语法可以通过（隐式将裸指针转成了智能指针匿名对象）。最危险的是作为函数参数传参时，裸指针会被意外隐式构造成一个临时的智能指针，函数执行完毕该临时对象析构，会导致传入的裸指针被提前 delete 释放。
   3. 在现实的 std::shared_ptr 中，控制块里只有这一个计数器吗？
   不是。标准库的控制块中除了强引用计数（shared_ptr 个数），还包含一个弱引用计数（weak_ptr 个数）以及自定义删除器（Deleter）。当强引用计数归零时，用户数据 m_ptr 会被立刻释放；但只有当弱引用计数也归零时，控制块本身的内存才会被 delete 销毁。
