多线程共享进程的「堆区」、「全局/静态存储区」、「代码区」以及「打开的文件描述符」，但各自独享独立的「栈区」和「寄存器状态」

------------------------------
## 1. 进程内存布局：共享与独显的物理图谱
当一个多线程进程运行时，它的虚拟地址空间被划分为不同的区域，线程对这些区域的访问权限截然不同：

       ┌────────────────────────────────────────────────────────┐
       │                 进程虚拟地址空间 (Shared)               │
       ├────────────────────────────────────────────────────────┤
       │ 代码区 (Code)    : 存放编译后的机器指令（所有线程可读）  │
       ├────────────────────────────────────────────────────────┤
       │ 全局/静态区 (Data): 存放全局变量、static 变量 (完全共享)│
       ├────────────────────────────────────────────────────────┤
       │ 堆区 (Heap)      : 通过 new/malloc 动态申请的内存 (完全共享)│
       ├────────────────────────────────────────────────────────┤
       │       线程 1 的栈区       │       线程 2 的栈区       │
       │     (Thread 1 Stack)    │     (Thread 2 Stack)    │
       │  存放局部变量、函数参数  │  存放局部变量、函数参数  │
       │     【线程私有 🔒】     │     【线程私有 🔒】     │
       └───────┬─────────────────────────┬──────────────────────┘
               ▼                         ▼
         【线程1 寄存器】          【线程2 寄存器】
         (PC, RSP, RAX...)         (PC, RSP, RAX...)
          【绝对私有 🔒】           【绝对私有 🔒】

------------------------------
## 2. 深入拆解：哪些是完全共享的？哪些是私有的？## 🤝 核心共享区域（高危并发地带）

   1. 堆区（Heap）：
   * 通过 new 或 malloc 申请的内存 [1]。只要一个线程拿到了这块内存的指针，其他任何线程都可以去读写它。
   2. 全局/静态存储区（Data & BSS Segment）：
   * 在函数外部定义的全局变量，以及用 static 修饰的静态变量。它们在程序生命周期内永远存在，所有线程随时可调。
   3. 代码区（Text Segment）：
   * 程序的机器指令。所有线程共享同一套代码逻辑，多个线程可以同时执行同一个函数。
   4. 内核资源（Kernel Resources）：
   * 进程打开的文件描述符（File Descriptors）、网络 Socket、信号处理函数（Signal Handlers）等 [1]。线程 A 打开一个文件，线程 B 可以直接去读写这个文件。
   
## 🔒 核心私有区域（线程的自留地）

   1. 栈区（Stack）：
   * 每个线程在创建时，操作系统都会为其分配一段独立的栈空间（通常为几兆字节）。
      * 栈里存放的是局部变量、函数形参和函数调用上下文（返回地址）。
      * 特例：虽然技术上线程 A 可以通过指针强行偷看线程 B 栈上的局部变量，但这属于极度危险的野指针行为（未定义行为），在设计上栈是绝对私有的。
   2. 寄存器状态与程序计数器（Registers & PC）：
   * 这是 CPU 内部的硬件状态。程序计数器（PC/RIP）记录了当前线程自己执行到了代码的哪一行，栈指针（RSP）指向自己独立的栈顶。当操作系统进行线程切换（Context Switch）时，必须单独保存每个线程的寄存器快照。

## ⚠️ 共享内存带来的“并发灾难”与解法
多线程共享内存带来了极高的通信效率（不需要复杂的 IPC 进程间通信），但也直接导致了多线程编程中 99% 的恶性 Bug：
## 1. 数据竞争（Data Race）
当两个或多个线程同时读写同一个共享变量，且至少有一个线程在进行写操作时，如果没有同步机制，该变量最终的值将取决于 CPU 的调度顺序（即不可预测）。
## 🛠️ 工业级三大标准解法：

* 互斥锁（std::mutex / Lock）：最传统的做法。当线程 A 想要访问堆区或全局变量时，先“加锁”，此时其他线程必须在外面排队死等，直到 A 访问完毕“解锁”。
* 原子操作（std::atomic）：对于简单的整型或布尔变量，使用无锁的原子操作（利用 CPU 的总线锁或缓存一致性协议），保证加减操作一步到位，不被拆分。
* 线程局部存储（TLS, Thread Local Storage）：如果你希望一个变量既像全局变量一样在各个函数间自由传递，又希望每个线程都拥有它的一份独立副本、互不干扰，可以在 C++ 中使用 thread_local 关键字修饰变量。
```cpp
// 示例：
int g_shared = 0;              // 🤝 真正全局共享：所有线程都在抢这一个
thread_local int g_private = 0; // 🔒 线程局部存储：每个线程都有一份独立的、互不影响的 g_private
```
