## 📊 TCP 协议生命周期全景图（三次握手与四次挥手）
TCP（传输控制协议）是面向连接的、可靠的传输层协议。它通过三次握手建立连接，通过四次挥手释放连接。
```
======================= 【建立连接：三次握手】 =======================
  Client (客户端)                                                Server (服务端)
      │                                                                │  LISTEN (监听)
      │  [第1次] SYN = 1, seq = x                                      │
      ├───────────────────────────────────────────────────────────────►│  SYN_RCVD (收到SYN)
SYN_SENT (发送SYN)                                                     │
      │                                                                │
      │  [第2次] SYN = 1, ACK = 1, seq = y, ack = x + 1                │
      │◄───────────────────────────────────────────────────────────────┤
      │                                                                │
      │  [第3次] ACK = 1, seq = x + 1, ack = y + 1                     │
      ├───────────────────────────────────────────────────────────────►│  ESTABLISHED (连接成功)
ESTABLISHED (连接成功)                                                  │
      │                                                                │
======================= 【释放连接：四次挥手】 =======================
FIN_WAIT_1 (发FIN)                                                     │  ESTABLISHED
      │  [第1次] FIN = 1, ACK = 1, seq = u, ack = z                    │
      ├───────────────────────────────────────────────────────────────►│  CLOSE_WAIT (被动关闭)
      │                                                                │  (此时仍可发送数据)
FIN_WAIT_2 (收ACK)                                                     │
      │  [第2次] ACK = 1, seq = v, ack = u + 1                         │
      │◄───────────────────────────────────────────────────────────────┤
      │                                                                │
      │  [第3次] FIN = 1, ACK = 1, seq = w, ack = u + 1                │
      │◄───────────────────────────────────────────────────────────────┤  LAST_ACK (最后确认)
TIME_WAIT (等待2MSL)                                                   │
      │                                                                │
      │  [第4次] ACK = 1, seq = u + 1, ack = w + 1                     │
      ├───────────────────────────────────────────────────────────────►│  CLOSED (彻底关闭)
      │                                                                │
  [ 2MSL定时器超时 ]                                                    │
      ▼                                                                ▼
   CLOSED (彻底关闭)
```
------------------------------
## 🧱 一、 三次握手流程、发送内容及作用
三次握手的核心目的是同步双方的初始序列号（ISN），并确认双方都具备完全的发送与接收能力。
## 1. 第一次握手：客户端 → 服务端

* 发送内容：
* 控制标志位：SYN = 1（表示请求同步/建立连接）。
   * 初始序列号：seq = x（客户端随机生成的初始值，通常基于时间戳和特定哈希算法）。
* 状态演变：客户端由 CLOSED 变为 SYN_SENT。
* 核心作用：客户端向服务端打招呼。服务端收到后，证明了客户端的发送能力正常、服务端的接收能力正常。

## 2. 第二次握手：服务端 → 客户端

* 发送内容：
* 控制标志位：SYN = 1（表示服务端也请求建立连接），ACK = 1（表示对客户端请求的确认）。
   * 确认号：ack = x + 1（表示期待收到客户端的下一个字节，代表对 seq = x 的安全接收）。
   * 初始序列号：seq = y（服务端自己随机生成的初始序列号）。
* 状态演变：服务端由 LISTEN 变为 SYN_RCVD。
* 核心作用：服务端向客户端回应并同时发起连接请求。客户端收到后，证明了服务端的发送与接收能力正常、客户端的发送与接收能力正常。

## 3. 第三次握手：客户端 → 服务端

* 发送内容：
* 控制标志位：ACK = 1（对服务端的建立请求做出最终确认）。
   * 序列号：seq = x + 1（客户端当前报文段的序列号）。
   * 确认号：ack = y + 1（代表对服务端 seq = y 的安全接收）。
* 状态演变：客户端发送后进入 ESTABLISHED；服务端收到后也进入 ESTABLISHED。
* 核心作用：客户端给予最后的确认。服务端收到后，证明了服务端的接收能力正常。(注：此时连接正式建立，第三次握手可以携带具体的用户应用层数据)。

## 🧱 二、 四次挥手流程、发送内容及作用
四次挥手的核心目的是安全地终止双向的数据传输。因为 TCP 是全双工的，每个方向的连接都必须单独关闭。(假设客户端主动断开连接)
## 1. 第一次挥手：客户端 → 服务端（主动关闭）

* 发送内容：
* 控制标志位：FIN = 1（表示数据发送完毕，请求释放连接），ACK = 1（照常确认之前的接收）。
   * 序列号：seq = u（等于客户端前面已传送数据的最后一个字节序号加 1）。
   * 确认号：ack = z（对之前收到数据的照常确认）。
* 状态演变：客户端进入 FIN_WAIT_1 状态。
* 核心作用：客户端告诉服务端：“我的数据全部发完了，我要关闭向你的发送通道了。”

## 2. 第二次挥手：服务端 → 客户端（被动关闭）

* 发送内容：
* 控制标志位：ACK = 1（确认收到断开请求）。
   * 序列号：seq = v（服务端当前的序列号）。
   * 确认号：ack = u + 1（对客户端 FIN 报文的确认）。
* 状态演变：服务端进入 CLOSE_WAIT 状态；客户端收到该包后进入 FIN_WAIT_2 状态。
* 核心作用：服务端回应客户端：“收到你的断开请求了。但我可能还有数据没发完，你先等等。”(此时 TCP 连接处于半关闭状态，客户端无法再发数据，但能接收服务端发来的剩余数据)。

## 3. 第三次挥手：服务端 → 客户端

* 发送内容：
* 控制标志位：FIN = 1（服务端数据发完，请求释放连接），ACK = 1（照常确认）。
   * 序列号：seq = w（在这期间服务端如果发了数据，序列号会变为 w）。
   * 确认号：ack = u + 1（重复前一次的确认号）。
* 状态演变：服务端进入 LAST_ACK 状态。
* 核心作用：服务端告诉客户端：“我的数据也发完了，我也要关闭向你的发送通道了。”

## 4. 第四次挥手：客户端 → 服务端

* 发送内容：
* 控制标志位：ACK = 1（做出最终确认）。
   * 序列号：seq = u + 1（客户端当前的序列号）。
   * 确认号：ack = w + 1（对服务端 FIN 报文的确认）。
* 状态演变：服务端收到后直接进入 CLOSED；客户端发送后进入 TIME_WAIT，在等待 2MSL（最大报文生存时间）后自动彻底进入 CLOSED。
* 核心作用：客户端给出最终应答。服务端收到后断开连接，客户端等待 2MSL 以防止最后的 ACK 丢失导致服务端重传 FIN，并确保网络中本次连接的所有“残留脏报文”自然消失。
